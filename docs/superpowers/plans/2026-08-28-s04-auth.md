# S04-AUTH Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a production-tested authentication subsystem for PVNaive with Argon2id passwords, opaque sessions, CSRF, RBAC, TOTP MFA, owner bootstrap, localhost API service, minimal login UI, and guarded Caddy exposure.

**Architecture:** The Go API uses `database/sql` with pgx stdlib and keeps management sessions opaque. Authenticated requests begin a PostgreSQL transaction, bind the existing signed RLS context with the SHA-256 session-token hash, enforce HTTP RBAC/CSRF, execute the handler in that transaction, then commit or roll back. PostgreSQL migration 0002 adds only authentication state and narrowly scoped SECURITY DEFINER helpers needed before RLS context exists.

**Tech Stack:** Go 1.24, PostgreSQL 18, `golang.org/x/crypto/argon2` v0.55.0, `github.com/jackc/pgx/v5` v5.10.0, React/TypeScript/Vite, systemd, Caddy.

**Spec:** `docs/superpowers/specs/2026-08-28-s04-auth-design.md`

## Global Constraints

- Product name is `PVNaive`; repository name remains unchanged.
- S03-DATABASE is PASSED; S05+ stay blocked until S04 production postflight passes.
- API listens on `127.0.0.1:8080` until validated reverse-proxy exposure.
- Caddy/NaiveProxy, SSH and firewall are not mutated before localhost integration passes.
- No JWT, default password, plaintext DB session token, secret-bearing logs, or reuse of the DB backup age key for MFA encryption.
- Passwords use Argon2id m=19456 KiB, t=2, p=1, salt=16 B, key=32 B.
- Session absolute lifetime is 12 hours; idle expiry is 1 hour and never exceeds absolute expiry.
- Browser session cookie is `__Host-pvnaive_session`; CSRF cookie is `__Host-pvnaive_csrf`.
- Unsafe methods require session-bound CSRF validation; SameSite is defense in depth only.
