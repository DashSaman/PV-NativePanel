# PVNaive

<p align="center">
  <img src="web/public/private-network.webp" alt="Private Network" width="120" />
</p>

**PVNaive** پنل مدیریتی حرفه‌ای برای **NaiveProxy** است: یک باینری Go با Caddy forward-proxy داخلی، PostgreSQL 18 و پنل React (Vite + TypeScript) زیر مسیر `/panel/`. مدیریت کاربران، حجم و اعتبار، اشتراک با QR دوگانه، مانیتورینگ زنده سرور، استخر گره‌ها با سوییچ خودکار به بهترین سرور، و نقش‌های مدیریتی — همه فارسی، RTL و با ارقام یکدست فارسی.

> وضعیت: **فعال روی `https://naive.softarg.ir/panel/`** · تست‌های Go و وب (۱۱۷) سبز · اسکیمای دیتابیس v34

## نصب تک‌خطی

روی هر سرور ابونتو/دبیان تازه، فقط این یک خط را اجرا کنید (به‌جای `panel.example.com` دامنه خودتان را بگذارید):

```bash
PVNAIVE_DOMAIN=panel.example.com bash <(curl -fsSL https://raw.githubusercontent.com/DashSaman/PV-NativePanel/main/docker/install.sh)
```

اسکریپت خودش مخزن را clone می‌کند، رمزهای قوی می‌سازد، ایمیج Docker را build و بالا می‌آورد و در پایان این‌ها را چاپ می‌کند:

| خروجی | مثال |
| --- | --- |
| آدرس پنل | `https://panel.example.com/panel/` |
| ایمیل و رمز مالک | `admin@xxxx.local` / رمز تصادفی (فقط یک‌بار نمایش) |
| اکانت آماده Naive | `naive+https://pvuser…:…@panel.example.com:443` |
| مسیر رازها | `/opt/pvnaive/PV-NativePanel/docker/data/.env` (سطح دسترسی 0600) |

نسخه دلخواه:

```bash
PVNAIVE_DOMAIN=panel.example.com \
PVNAIVE_OWNER_EMAIL=admin@example.com \
PVNAIVE_OWNER_PASSWORD='رمز-دلخواه-قوی' \
PVNAIVE_BRANCH=main \
bash <(curl -fsSL https://raw.githubusercontent.com/DashSaman/PV-NativePanel/main/docker/install.sh)
```

اگر بدون `PVNAIVE_DOMAIN` اجرا کنید، IP سرور جای دامنه می‌نشیند و گواهی self-signed ساخته می‌شود — پنل بالا می‌آید ولی مرورگر هشدار گواهی می‌دهد؛ برای گواهی معتبر Let's Encrypt دامنه را A-Record کنید و با `PVNAIVE_DOMAIN` نصب کنید.

## پیشنیازها

- **سرور**: Ubuntu 20.04+ یا Debian 11+ با حداقل ۱ گیگ RAM و ۱۰ گیگ دیسک.
- **دسترسی root** (sudo).
- **Docker + Compose v2** — اگر نصب نیست: `curl -fsSL https://get.docker.com | sh`
- **دامنه با A-Record به IP سرور** — فقط برای گواهی معتبر TLS لازم است؛ بدون دامنه هم با IP و self-signed کار می‌کند.
- پورت‌های **80 و 443** آزاد باشند.

به‌روزرسانی نسخه بعدی، همان دستور تک‌خطی را دوباره اجرا کنید — تنظیمات و داده‌ها در `data/` ماندگارند و مایگریشن‌ها فقط-جلو خودکار اعمال می‌شوند.

## راهنمای پنل

### ورود — `#/login`

- کارت دو تکه «Gold Reception»: پنل برند با لوگوی طلایی و شناور سه‌بعدی + فرم ورود با **فیلدهای ایمیل و رمز همیشه نماینده** (آیکون، برچسب و حلقه فوکوس طلایی).
- چشمِ نمایش رمز، کد TOTP در صورت فعال‌بودن MFA، و دکمه «ورود امن» با افکت براق.
- ورود، کوکی امن `__Host-pvnaive_session` + توکن CSRF صادر می‌کند.

### داشبورد — `/`

- **کارت‌های آماری** — کل کاربران، فعال‌ها، پلن‌ها، نیازمند توجه؛ با هاور، کارت با پرسپکتیو سه‌بعدی بالا می‌آید.
- **توزیع سرویس‌ها (دونات)** — فعال / منتظر اتصال / تعلیق / پایان‌یافته با درصد هر بخش.
- **۷ و ۳۰ روز آینده** — حساب‌های در آستانه انقضا.
- **مانیتورینگ زنده سرور**:
  - نشان «زنده · هر ۱ ثانیه» — سبز = استریم SSE فعال؛ کهربایی = نمونه‌برداری دوره‌ای.
  - **گیج‌های پردازنده / حافظه / دیسک** — مرکز گیج همیشه **درصد** است و چیپ زیر آن مصرف واقعی (مثلاً `۲٫۱ GB / ۵۰ GB`)؛ رنگ آستانه‌ای: سبز < ۷۵٪، کهربایی < ۹۰٪، قرمز ≥ ۹۰٪.
  - **نمودار زنده ترافیک شبکه** — دریافت/ارسال با برچسب‌های HTML شارپ (بدون کشیدگی)، هاله نورانی خطوط و پنجره ۹۰ نمونه.
  - آپ‌تایم + بار سیستم + اینترفیس — همه با ارقام فارسی.
- همه اعداد پنل با **ارقام فارسی یکدست** نمایش داده می‌شوند.

## اشتراک و تحویل QR

| مسیر | مخاطب | رفتار |
| --- | --- | --- |
| `/sub/<token>` | کلاینت‌ها | خروجی ماشینی بر اساس User-Agent: naive خام، sing-box (Karing)، Clash/Mihomo، base64 v2ray. **باز کردن با مرورگر به‌جای دانلود فایل، به صفحه حساب هدایت می‌شود.** با `?family=` قابل اجبار است. |

## اتصال کلاینتها

کلاینت‌های تأییدشده — **Karing** (پیشنهادی) و **NekoBox / NekoRay**. بقیه کلاینت‌ها naive+https را پشتیبانی نمی‌کنند.

| کلاینت | پلتفرم | سریع‌ترین روش |
| --- | --- | --- |
| **Karing** (پیشنهادی) | اندروید / iOS / ویندوز / مک | «+» ← اسکن QR ساب — پروفایل با نام `PVNaive-<نام‌کاربری>` ثبت می‌شود |
| NekoBox / NekoRay | اندروید / کامپیوتر | گروه subscription یا ایمپورت `naive+https://` از کلیپ‌بورد |

- بعد از اتصال، وضعیت صفحه حساب «فعال / آنلاین» می‌شود.
- بعد از تغییر حجم/رمز، ساب را Refresh کنید.
- اگر وصل نشد: QR مستقیم Naive را امتحان کنید.

## گره جدید

> 📚 **راهنمای تصویری گام‌به‌گام:** [docs/NODE_TUTORIAL_FA.md](docs/NODE_TUTORIAL_FA.md) — افزودن گره با
> تصویر برای تمام مراحل (صدور توکن، ثبت‌نام، انتشار مانیفست امضاشده، تأیید سلامت) + عیب‌یابی.
>
> ⛔ **قانون Cloudflare:** دامنه‌ی هر سرور naive (اصلی و گره‌ها) باید ابر **خاکستری (DNS Only)** باشد؛
> ابر نارنجی تونل `CONNECT` را با خطای 400 قطع می‌کند. «الان کار می‌کند» یعنی هنوز کش DNS قدیمی فعال است.

سوییچ خودکار به بهترین سرور، همان قابلیتی است که از اول درخواست شد — «چند سرور اضافه کنم و خود پنل بهترین را انتخاب کند». مسیر کامل:

1. **سرور دوم را مثل سرور اول نصب کنید** — همان [دستور تک‌خطی](#نصب-تکخطی) با دامنه/IP همان سرور. این سرور یک «گره» می‌شود.
2. **در پنل سرور اصلی** وارد `#/pool` شوید و روی **«صدور توکن ثبت»** بزنید — توکن یک‌بار نمایش داده می‌شود؛ همان لحظه کپی کنید.
3. گره را با همان توکن ثبت کنید (نام گره + توکن + آدرس سرویس). بعد از ثبت، پنل **اعتبار کاربران را روی گره همگام** می‌کند و برای آن **مانیفست امضاشده** منتشر می‌کند.
4. گره در جدول باید **سبز و هم‌گام (Applied = Desired)** شود؛ اگر در حال تعمیر (Maintenance) است، از همان صفحه خارج کنید.
5. تمام! از این به بعد هر کاربری که ساب را Refresh کند، **همه گره‌های سالم** داخل پروفایلش می‌آیند:
   - در Karing/sing-box یک گروه **`PV-AUTO` (urltest)** ساخته می‌شود که هر ۵ دقیقه همه گره‌ها را تست می‌کند (تحمل ۵۰ms) و همیشه از **سریع‌ترین** استفاده می‌کند.
   - در Mihomo/Clash همان رفتار با گروه url-test از طریق proxy-provider (به‌روزرسانی داغ هر ۴ ساعت) انجام می‌شود.
   - حذف/خرابی یک گره چیزی را نمی‌شکند: کلاینت خودش به بعدی سوییچ می‌کند.

> نکته: اعتبار هر کاربر روی همه گره‌ها یکسان است؛ مصرف کل در دیتابیس پنل تجمیع و بر همان اساس کنترل می‌شود. حالت تعمیر گره را از ساب خارج می‌کند بدون اینکه کاربر متوجه شود.

## معماری

```
┌────────────────────────── کانتینر pvnaive ─────────────────────────────┐
│  پنل React (/panel)     Go API (:8080)     Caddy (:80/:443)            │
│   ├─ بیلد Vite           ├─ /api/v1/*        ├─ TLS (Let's Encrypt)     │
│   ├─ تم گلس RTL          ├─ استریم SSE       ├─ forward_proxy (naive)   │
│   └─ کدکننده QR محلی     ├─ نقش‌های RBAC     ├─ /sub ، /s ، /panel      │
│                          ├─ accounting        └─ سوکت accounting ◄─────┤
│                          └─ fleet/pool mTLS        شمارش دقیق بایت    │
│  PostgreSQL 18 (اسکیمای v34، مایگریشن‌های فقط-جلو، بکاپ رمزشده)        │
└─────────────────────────────────────────────────────────────────────────┘
```

- **Accounting دقیق بایت**: رزرو → تسویه به تفکیک اعتبار و نشست؛ baseline مقاوم به ری‌استارت؛ resetهای auditable.
- **رکونسیلر رزروهای رهاشده** (v34): کرش بین رزرو و تسویه دیگر کاربر را قفل نمی‌کند؛ گیت اتصال فقط به رزروهای در جریان حساس است.
- **اعتبار از اولین اتصال** فقط با CONNECT احراز‌هویت‌شده شروع می‌شود.
- **Steering / cover** (پیش‌فرض خاموش) و **fleet mTLS pull** سیم‌کشی شده‌اند.

## مدل امنیتی

- نشست‌ها: `__Host-pvnaive_session` + CSRF؛ MFA (TOTP + کد بازیابی).
- اسرار: رمزهای Runtime با AES-GCM؛ توکن اشتراک SHA-256؛ رمزهای تولیدی فقط یک‌بار نمایش.
- عملیات فقط‌خواندنی (دیدن QR، کپی لینک) با تست قراردادی اثبات شده که هیچ stateی را عوض نمی‌کنند.
- صفحه `/s/` خصوصی است: `noindex` + هدرهای قفل‌شده.

## اعتبار طراحی

روش‌شناسی بصری (سطوح گلس، لایه‌بندی عمقی، سیستم اکسنت طلایی، حرکت‌های hover/tilt) از دیتاست متن‌باز **[ui-ux-pro-max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)** — پروفایل‌های Glassmorphism، Dimensional Layering و Real-Time Monitoring — و با فارسی‌سازی RTL به کمک Vazirmatn و JetBrains Mono تطبیق داده شده است.
